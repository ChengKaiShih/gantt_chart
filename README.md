# 工程甘特圖排程工具

一套以工程規劃與施工期程為情境設計的瀏覽器甘特圖工具。使用者輸入工項的開始日期、完成日期及前置關係後，系統會自動計算日曆工期、總浮時及要徑，並以日、週、月、季或年檢視期程。

本專案目前為 **V1 初版（0.1.0）**，重點是先建立可操作、可驗證且容易持續修改的排程基礎。

## 目前功能

- 表格式輸入工項名稱、開始日期、完成日期及主要控制說明
- 自動計算起訖日均計入的日曆工期
- 多層 WBS 工項，可新增下階工項、縮排、取消縮排、排序及收合
- 上階工項自動彙整所有下階工項的最早開始日與最晚完成日
- 日、週、月、季、年五種時間尺度
- FS、SS、FF、SF 四種前置關係
- 正負時間間隔（lag／lead）
- CPM 網圖計算、總浮時及要徑標示
- 計畫日期與前置關係衝突提示
- 瀏覽器本機自動儲存
- JSON 專案檔匯出與匯入
- 內建道路工程期程範例

## 直接使用

開啟發布後的 GitHub Pages 網址即可使用，不需要登入，也不會把工程期程資料上傳至 GitHub。

專案資料儲存在目前瀏覽器的 `localStorage`。更換電腦、瀏覽器或清除網站資料前，請先使用「匯出」下載 JSON 備份；在其他裝置可再使用「匯入」接續編輯。

## 日期與要徑計算規則

1. 開始日與完成日均計入工期。例如 2026-01-01 至 2026-01-10 為 10 個日曆日。
2. V1 由使用者輸入計畫日期，系統不會自行覆寫日期。
3. CPM 依最下階工項的工期、前置關係及時間間隔另行計算最早／最晚時點與總浮時。
4. 總浮時為 0 的最下階工項標示為要徑。
5. 若計畫日期早於前置邏輯允許的日期，介面會顯示衝突提示。
6. 上階工項僅作 WBS 彙整，不直接參與 CPM 計算。

關係類型：

| 代碼 | 說明 |
|---|---|
| FS | 前項完成後，後項開始 |
| SS | 前項開始後，後項開始 |
| FF | 前項完成後，後項完成 |
| SF | 前項開始後，後項完成 |

時間間隔以日曆日輸入；正值表示延遲，負值表示提前。

## 本機開啟

本專案沒有第三方執行套件，可使用任一靜態網頁伺服器開啟 `dist` 目錄。例如已安裝 Python 時：

```bash
python -m http.server 8000 --directory dist
```

接著開啟 `http://localhost:8000`。

## 檢查

需 Node.js 18 以上：

```bash
npm test
npm run check
```

## 專案結構

```text
dist/
  index.html          # 網頁結構
  styles.css          # 介面與甘特圖樣式
  app.js              # 操作、儲存及畫面繪製
  schedule-core.js    # 日期、階層彙整與 CPM 計算
tests/
  schedule-core.test.mjs
docs/
  PROJECT_SPEC.md     # V1／V2 範圍及設計決策
```

## 開發路線

### V1

- 完成目前的階層式工項、起訖日期、時間尺度、前置關係、時間間隔及 CPM 要徑基礎
- 持續依實際操作調整表格、時間軸及編輯流程
- 強化資料驗證與匯入匯出可靠性

### V2

- 預定進度、實際進度與完成百分比
- 基準期程比較
- 里程碑及前後關係箭頭
- 拖曳甘特橫條調整日期
- 工作日曆、週休及國定假日
- Excel 匯入匯出
- 高解析度 PNG 與適合簡報／報告的 PDF 輸出
- 要徑、逾期及未完成工項篩選
- 視需求評估多專案管理或雲端同步

完整範圍與決策請參閱 [`docs/PROJECT_SPEC.md`](docs/PROJECT_SPEC.md)。

## 發布

推送至 `main` 後，GitHub Actions 會將 `dist` 目錄部署至 GitHub Pages。第一次使用時，請在儲存庫的 **Settings → Pages** 確認來源設定為 **GitHub Actions**。
